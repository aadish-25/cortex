# Deployment — Cortex (AAD-H1)

DO NOT edit this file until the application is fully built and tested locally.

---

## Target Platform

Railway — all services (FastAPI, PostgreSQL, Redis, Qdrant) deployed as Railway services within one project.

---

## Services

| Service | Railway Type | Notes |
|---|---|---|
| `cortex-api` | Web service (Python) | FastAPI app |
| `cortex-db` | PostgreSQL plugin | Managed by Railway |
| `cortex-redis` | Redis plugin | Managed by Railway |
| `cortex-qdrant` | Docker service | `qdrant/qdrant` image |
| `cortex-worker` | Worker service | Celery worker, same codebase as API |

---

## Environment Variables (set in Railway dashboard)

All variables from `.env.example` must be set in the Railway service environment. Railway injects `DATABASE_URL`, `REDIS_URL` automatically for managed plugins — verify variable names match what `config.py` expects.

---

## Start Commands

API: `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`

Worker: `celery -A backend.worker.celery_app worker --loglevel=info`

---

## Health Check

`GET /health` → `{"status": "ok"}`

Railway uses this for zero-downtime deploys.
